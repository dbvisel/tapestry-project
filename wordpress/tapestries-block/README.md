# Tapestries Block (WordPress)

A WordPress block that embeds an exported **Tapestry ZIP** as an interactive, zoomable viewer inside a
post or page. In the editor the author picks the **Tapestry** block, uploads/selects a Tapestry ZIP from
the Media Library, and the tapestry renders inline (an `<iframe>` hosting the bundled viewer).

## How it works

This plugin wraps the existing standalone Tapestry **viewer** (the `viewer/` workspace in this repo) — the
same app that lets you drop an exported ZIP and renders it entirely in the browser.

- **Editor** (`editor.js`): a dynamic block. The author uploads/selects a ZIP via the Media Library; the
  block stores the attachment URL (`zipUrl`), an optional title, and a `height`. A live preview iframe is
  shown in the editor.
- **Front end** (`tapestries-block.php` → `tapestries_block_render`): the block is rendered server-side to
  an `<iframe>` pointing at the bundled viewer with `?source=<zipUrl>`:

  ```
  /wp-content/plugins/tapestries-block/viewer/index.html?source=<urlencoded ZIP url>
  ```

  The viewer fetches that ZIP, unpacks it in the browser (`@zip.js/zip.js`), runs the tapestry-core export
  parser, and renders the tapestry on a PIXI canvas. **No ZIP processing happens on the server.**

Because the viewer assets and the uploaded ZIP are both served from the WordPress domain, the viewer's
`fetch(source)` is same-origin — no CORS configuration needed. (If you point `zipUrl` at a ZIP on another
host, that host must send permissive CORS headers.)

## Files

| File | Purpose |
|------|---------|
| `tapestries-block.php` | Plugin entry: registers the block, the dynamic `render_callback`, and an `upload_mimes` filter that allows `.zip` uploads. |
| `block.json` | Block metadata + attributes (`zipUrl`, `zipId`, `title`, `height`) + shared `style.css`. |
| `editor.js` | Buildless editor UI (uses the global `wp.*` packages — no build step). |
| `style.css` | Shared editor/front-end styles. |
| `viewer/` | A **bundled copy of the Tapestry viewer**, built with a relative asset base. Generated by `build-viewer.sh`. |
| `build-viewer.sh` | Rebuilds the viewer (`vite build --base=./`) and copies it into `viewer/`. |
| `package-plugin.sh` | One command: builds the viewer **and** produces an upload-ready ZIP. |

> `viewer/` and the packaged ZIP are build artifacts (git-ignored) — both are reproducible with the scripts
> below.

## Packaging for upload (one command)

```sh
cd wordpress/tapestries-block
./package-plugin.sh
```

This builds the bundled viewer and writes an upload-ready archive to **`wordpress/dist/tapestries-block.zip`**
— a single top-level `tapestries-block/` folder, exactly what WordPress's *Upload Plugin* expects.

Flags:
- `./package-plugin.sh --skip-build` — package only, reusing the existing `viewer/` (skip the viewer rebuild).

To rebuild just the bundled viewer without packaging, run `./build-viewer.sh` (builds with `--base=./` so its
assets load from this sub-directory, then copies the output into `viewer/`).

## Installing in WordPress

**Option A — upload the ZIP (recommended):**
1. `./package-plugin.sh`
2. In WordPress: **Plugins → Add New → Upload Plugin**, choose `wordpress/dist/tapestries-block.zip`, install, activate.

**Option B — copy the folder:**
1. `./build-viewer.sh` so `viewer/` exists.
2. Copy the `tapestries-block/` directory into `wp-content/plugins/`.
3. Activate **Tapestries Block** in **Plugins**.

## Using it

1. Edit a post/page → add the **Tapestry** block.
2. Click **Select Tapestry ZIP** and upload (or choose) an exported Tapestry `.zip`.
3. Optionally set the **Height** in the block sidebar.
4. Publish. The tapestry renders inline in the post.

## Notes & limitations

- **ZIP uploads**: WordPress blocks `.zip` uploads by default; this plugin re-enables them via
  `upload_mimes`. Administrators can upload; on some multisite setups non-admins may need the
  `unfiltered_upload` capability.
- **Height**: a tapestry is an infinite canvas with no intrinsic size, so the iframe needs an explicit
  height (default 600px), set per-block.
- **Bundle size**: the viewer bundle (PIXI + tapestry-core-client) is a few MB. WordPress only loads it on
  pages that actually contain the block, and the iframe is `loading="lazy"`.
- **IIIF items**: tapestries containing the `iiif` item type render here as-is (the viewer uses
  tapestry-core-client's default components). Deep-zoom for IIIF items still streams tiles from the
  external IIIF server, so those specific items require network access even when the rest of the ZIP is
  self-contained.
- This is an **iframe embed** (v1). A future option is a no-iframe "native" mount; the block/PHP scaffolding
  here would stay the same — only the front-end output would change.
